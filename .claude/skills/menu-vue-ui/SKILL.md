# Vue 채팅 UI 변경

API shape 은 `_workspace/01_architect_contracts.md` 가 원천이다. 화면에서 쓰는 필드는 계약에 있는 이름 그대로 쓴다. 필드 이름 하나 틀리면 카드가 빈 칸으로 나오고 오류도 안 난다 — 이 프로젝트에서 가장 흔한 경계면 버그다.

## 0. sample 관례 유지
sample 의 web_chat.html 이 Vue 를 어떻게 불러오는지(CDN, 버전), API 기본 URL 과 프록시(web_demo_server.py), 세션/사용자 id 를 어떻게 만드는지, 메시지 렌더링 구조를 읽고 그 틀 안에서 바꾼다. 빌드 도구를 새로 들이지 않는다 — 단일 HTML 구조가 실행 순서(run_frontend.sh)의 전제다.

## 1. 바꿀 것
| 영역 | 내용 |
|---|---|
| 제목·안내 | "오늘뭐먹지" + 한 줄 설명. 장애 진단 문구는 모두 제거 |
| 예시 칩 | 노트북 case1~3 문장. 클릭하면 입력창에 채움 — 시연 시 타이핑 시간을 줄인다 |
| 추천 카드 | `kept[]` 를 카드로: 메뉴명, 가격(천 단위 콤마), 시간, 이유. 카드마다 "먹었어요" 버튼 |
| 완화 안내 | `relaxed[]` 가 있으면 카드 위 첫 줄에 강조 표시. 문구는 프론트가 만든다(LLM 문장 아님) |
| 승인 대화 | `status==="needs_approval"` 이면 proposal 을 "예산을 5,000원 → 8,500원으로 올려서 찾아볼까요?" 로 보여 주고 승인/거절 버튼 → `/chat/resume` |
| 리뷰 표시 | `review_flags[]` 가 있으면 해당 카드에 "이유 문장을 데이터 기준으로 고쳤어요" 작은 배지 |
| 처리 흐름 | `trace`(지나간 노드 목록)를 접이식으로. 발표에서 그래프 경로를 보여 주는 용도 |
| 식사 기록 | 사이드 또는 하단에 최근 먹은 메뉴 목록(`GET /meals`) |
| 일반 대화 | 추천이 아닌 응답은 기존 말풍선 그대로 |

## 2. 상태와 오류
- 요청 중에는 전송 버튼 비활성 + 로딩 표시. 승인 대기 중에는 새 메시지 전송을 막거나, 보내면 대기 중인 승인을 취소한다는 안내를 띄운다. 둘 중 무엇을 할지는 계약 문서의 resume 규칙을 따른다.
- 4xx/5xx 응답은 서버가 준 메시지를 말풍선으로 보여 준다. 콘솔에만 찍으면 시연 때 아무 반응 없는 화면이 된다.
- 빈 입력은 전송하지 않는다.

## 3. 완료 기준
- fake provider 백엔드로 case1~3 을 화면에서 눌러 카드·완화 안내·승인 버튼·먹었어요가 동작한다.
- 브라우저 콘솔 에러 0. 가능하면 claude-in-chrome 으로 스크린샷을 남겨 `_workspace/04_frontend_screens/` 에 저장한다(README 실행 화면에 재사용).
- 사용한 API 필드 목록을 `_workspace/04_frontend_fields.md` 에 적는다. QA 가 계약과 교차 비교한다.
